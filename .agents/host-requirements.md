# Project and host prerequisites

The recommended core discovers inputs from the assigned project rather than requiring this library's own layout. A missing input is reported, not fabricated.

| Input | How to resolve it |
| --- | --- |
| Repository instructions and contribution conventions | Read the actual governing files available in the target project |
| Requirements, decisions, and acceptance criteria | Use the assignment and accepted project artifacts; distinguish proposals from adopted decisions |
| Build and test configuration | Inspect the selected language, framework, existing runner, and established commands |
| Templates and output locations | Reuse project conventions when present; otherwise choose a proportionate format for the request |
| Data or sample sources | Use supplied or verified bundled files; label authorized synthetic data explicitly |
| Tools and delegation | Use actual host capabilities and permissions; sequential work is a supported fallback |

Optional stack, architecture, provider, and domain collections can require additional context described in their entrypoints. For example, VBD work depends on the consuming project's accepted design; a platform deployment needs the assigned environment and operation authority.

No skill requires a provider-specific skill-invocation mechanism merely to read instructions. Skill selection and collection membership do not authorize installation, delegation, messaging, commits, publishing, or live operations.
