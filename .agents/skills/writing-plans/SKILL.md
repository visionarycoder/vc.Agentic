# Write an implementation plan

Use when work needs a durable sequence, multiple dependencies, or an explicit plan. Simple reversible edits may not need a separate plan artifact.

1. Read the request, applicable instructions, relevant code/docs, and existing decisions. Gather accessible facts before asking for missing choices.
2. State the outcome, scope, constraints, assumptions, and decisions still requiring an owner.
3. Break work into coherent steps. Identify dependencies, expected behavior, affected boundaries, and meaningful checks. Avoid speculative file paths or invented APIs.
4. Distinguish accepted decisions from proposals. Do not imply that a written plan grants implementation or operation authority.
5. Use the project's plan format and location when present. Otherwise choose a simple location appropriate to the request; no fixed directory or provider task tool is required.
6. Include validation, integration considerations, and material risks. Keep detail proportional to complexity. Do not add mandatory delegation, commits, or review ceremonies unless required by the actual assignment.
