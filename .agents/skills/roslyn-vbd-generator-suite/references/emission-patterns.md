# Code Emission Patterns

Best practices for generating clean, maintainable C# code from Roslyn generators.

## String Interpolation vs. StringBuilder vs. Syntax Factories

**String interpolation** — Best for small, simple generation (< 50 lines):
```csharp
var code = $$"""
namespace {{namespaceName}};

public class {{className}}
{
    public string Name { get; init; }
}
""";
```

**StringBuilder** — Best for medium complexity (50-200 lines):
```csharp
var sb = new StringBuilder();
sb.AppendLine($"namespace {namespaceName};");
sb.AppendLine();
sb.AppendLine($"public class {className}");
sb.AppendLine("{");
foreach (var prop in properties)
{
    sb.AppendLine($"    public {prop.Type} {prop.Name} {{ get; init; }}");
}
sb.AppendLine("}");
return sb.ToString();
```

**Syntax factories** — Best for complex generation requiring semantic awareness:
```csharp
var classDecl = ClassDeclaration(className)
    .AddModifiers(Token(SyntaxKind.PublicKeyword))
    .AddMembers(properties.Select(p =>
        PropertyDeclaration(ParseTypeName(p.Type), p.Name)
            .AddModifiers(Token(SyntaxKind.PublicKeyword))
            .AddAccessorListAccessors(
                AccessorDeclaration(SyntaxKind.GetAccessorDeclaration)
                    .WithSemicolonToken(Token(SyntaxKind.SemicolonToken)),
                AccessorDeclaration(SyntaxKind.InitAccessorDeclaration)
                    .WithSemicolonToken(Token(SyntaxKind.SemicolonToken)))
    ).ToArray());
```

**Recommendation:** Use string interpolation for most generators. It's readable, maintainable, and fast enough. Reserve syntax factories for when you need precise semantic control.

## Namespace and Using Directives

**File-scoped namespaces** (preferred):
```csharp
var code = $$"""
namespace {{namespaceName}};

using System;
using System.Collections.Generic;

public class {{className}} { }
""";
```

**Sort and deduplicate usings:**
```csharp
var usings = requiredNamespaces
    .Distinct()
    .OrderBy(ns => ns)
    .Select(ns => $"using {ns};");

var usingBlock = string.Join("\n", usings);
```

**Global usings** — Avoid generating them; let the project handle common imports.

## Nullable Reference Types

Always emit nullable annotations to match modern C# conventions:

```csharp
public string? OptionalProperty { get; init; }
public string RequiredProperty { get; init; } = null!;
public List<string> Items { get; init; } = new();
```

For parameters:
```csharp
public void Process(string input, string? optionalParam = null)
```

## XML Documentation

Generate XML docs for public APIs:

```csharp
var code = $$"""
/// <summary>
/// {{summary}}
/// </summary>
{{#if remarks != null}}
/// <remarks>
/// {{remarks}}
/// </remarks>
{{/if}}
public class {{className}} { }
""";
```

For generated code, include a note:
```csharp
/// <summary>
/// Auto-generated from {{sourceType}}.
/// </summary>
/// <remarks>
/// This code is generated by {{generatorName}}. Do not modify directly.
/// </remarks>
```

## Attribute Preservation

Forward relevant attributes from source to generated code:

```csharp
var attributes = symbol.GetAttributes()
    .Where(attr => ShouldPreserve(attr))
    .Select(attr => attr.ToString());

var attrBlock = attributes.Any()
    ? string.Join("\n", attributes.Select(a => $"[{a}]")) + "\n"
    : "";
```

## Partial Classes and Methods

**Partial classes** — Use when augmenting user-written code:
```csharp
namespace MyApp.Models;

public partial class Customer
{
    // Generated members
    partial void OnNameChanged(string value);
}
```

**Partial methods** — Hooks for user customization:
```csharp
partial void OnValidating();
partial void OnValidated();

public void Validate()
{
    OnValidating();
    // Generated validation logic
    OnValidated();
}
```

## Record Types

For DTOs and value objects, emit records:

```csharp
public record {{typeName}}(
    {{string.Join(",\n    ", properties.Select(p => $"{p.Type} {p.Name}"))}}
);
```

For records with validation:
```csharp
public record {{typeName}}
{
    public required {{type}} {{name}} { get; init; }

    public {{typeName}}
    {
        if (string.IsNullOrWhiteSpace({{name}}))
            throw new ArgumentException("Cannot be empty", nameof({{name}}));
    }
}
```

## Immutability Patterns

Prefer init-only properties:
```csharp
public string Name { get; init; }
```

For collections:
```csharp
public IReadOnlyList<string> Items { get; init; } = Array.Empty<string>();
```

## Error Handling in Generated Code

Generated code should fail fast with clear messages:

```csharp
if (input is null)
    throw new ArgumentNullException(nameof(input));

if (string.IsNullOrWhiteSpace(input.Name))
    throw new ArgumentException("Name cannot be empty", nameof(input));
```

For validation results:
```csharp
public ValidationResult Validate()
{
    var errors = new List<string>();

    if (string.IsNullOrWhiteSpace(Name))
        errors.Add("Name is required");

    return errors.Any()
        ? ValidationResult.Failure(errors)
        : ValidationResult.Success();
}
```

## GeneratedCode Attribute

Mark all generated types:

```csharp
using System.CodeDom.Compiler;

[GeneratedCode("{{generatorName}}", "{{version}}")]
public class {{className}} { }
```

This helps tools skip generated code in coverage and analysis.

## File Naming Conventions

- Single type: `{TypeName}.g.cs`
- Multiple related types: `{BoundaryName}.{Component}.g.cs`
- Registration/setup: `{BoundaryName}.Registration.g.cs`
- Extensions: `{TargetType}Extensions.g.cs`

Always use `.g.cs` suffix to indicate generated code.

## Indentation and Formatting

Use consistent 4-space indentation:

```csharp
var indent = new string(' ', level * 4);
sb.AppendLine($"{indent}public class {className}");
sb.AppendLine($"{indent}{{");
// members
sb.AppendLine($"{indent}}}");
```

Or use raw string literals with proper indentation:
```csharp
var code = $$"""
    namespace {{ns}};

    public class {{name}}
    {
        public string Property { get; init; }
    }
    """;
```

## Avoiding Name Collisions

Use fully-qualified names in generated code when ambiguity is possible:

```csharp
public System.Collections.Generic.List<string> Items { get; init; }
```

Or generate unique names:
```csharp
var uniqueName = $"{baseName}_{Guid.NewGuid():N}";
```

## Conditional Compilation

Include debug helpers in generated code:

```csharp
#if DEBUG
[System.Diagnostics.DebuggerDisplay("{DebugDisplay}")]
private string DebugDisplay => $"{{Name}}: {{Value}}";
#endif
```

## Performance Considerations

- **Reuse StringBuilder instances** across multiple emissions
- **Avoid string concatenation in loops** — use StringBuilder or interpolation
- **Cache repeated strings** — namespace names, common types
- **Use spans** for substring operations when processing large inputs
- **Minimize allocations** — prefer `stackalloc` for small, fixed buffers

## Testing Generated Output

Use snapshot testing with Verify:

```csharp
[Fact]
public Task GeneratesExpectedCode()
{
    var source = """[MyAttribute] public class Test { }""";
    var output = RunGenerator(source);
    return Verify(output);
}
```

Store snapshots in `*.verified.cs` files for review.
