# Execute a plan

1. Read the plan, applicable instructions, current files, and actual assignment. Confirm the intended result and identify dependencies and unresolved decisions.
2. Use the existing workspace unless isolation is needed or required. Do not create a worktree, branch, or task system merely because a workflow example names one.
3. Implement a coherent step, run checks appropriate to its impact, and inspect the result. Track progress in the project's existing format when one exists.
4. Resolve routine choices within scope. Report missing evidence and route decisions outside the assignment to the responsible owner. Preserve unaffected work.
5. Coordinate dependencies before integration. Use delegated execution only when authorized and available; sequential execution is a complete supported path.
6. Report changed behavior, verification, and remaining work. Do not treat plan completion as permission to commit, publish, deploy, or close a governed phase.
