# Focused implementation

Use when a task would benefit from bounded context and incremental implementation.

1. Read applicable instructions and the smallest relevant set of requirements, code, tests, and decisions. Discover their actual locations instead of requiring named roadmap files or a particular framework.
2. Identify the requested outcome, affected boundaries, acceptance checks, and unresolved decisions. Preserve existing contracts and concurrent work.
3. Implement a coherent slice using existing mechanisms where appropriate. Avoid adding abstractions, prompts, plans, or tooling that do not help this assignment.
4. Run checks appropriate to the change's impact. Reuse valid evidence while its context remains current; repeat checks when changes or failures justify it.
5. Keep correctness and scope ahead of token savings. Report missing evidence rather than hiding a failed criterion or claiming unperformed work.
6. Summarize behavior, verification, and material limits. Project architecture, test thresholds, and operational authority come from the consuming project, not this skill.
