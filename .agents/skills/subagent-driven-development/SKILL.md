# Delegated implementation

Use only when delegated execution fits the assignment and is authorized. For sequential execution use [executing plans](../executing-plans/SKILL.md).

1. Read the accepted plan, scope, current repository state, dependencies, and required reviews. Identify which decisions remain outside the worker's authority.
2. Divide work into bounded tasks with observable acceptance checks. Assign a worker using the actual host capability and relevant context.
3. After each task, inspect changes and evidence. Arrange separate critique when the governing workflow requires it; do not label self-review independent.
4. Incorporate routine implementation findings within accepted bounds. Escalate design or authority conflicts to the responsible owner; a worker's ruling does not override governing decisions.
5. Integrate and verify dependent tasks in the assigned workspace. Review the combined change, document remaining limitations, and preserve concurrent edits.
6. Continue authorized work without unnecessary confirmation loops. Commits, messages to others, publishing, and live operations still require their existing authorization.

If delegation or independent review is unavailable, report the limitation and use an authorized sequential path. This skill does not create roles or establish acceptance gates of its own.
