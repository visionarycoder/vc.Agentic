# Design interview

Use when the user asks to be interviewed or to stress-test a plan, decision, or idea.

1. Read the supplied context and identify decisions, assumptions, and dependencies. Check accessible facts directly instead of asking the user to retrieve them.
2. Ask a bounded round of consequential questions whose prerequisites are already settled. Number questions, explain the tradeoff, and give a recommendation where the evidence supports one.
3. Incorporate answers before asking dependent questions. Reuse established decisions and avoid repeating settled questions.
4. Continue until the requested scope is understood. Summarize decisions, unresolved questions, and assumptions; keep proposals distinct from adopted decisions.
5. For a documentation-assisted interview, use the domain-modeling workflow and draft requested ADRs or glossary updates. Interview completion does not approve the design or authorize implementation.

Delegate factual research only when the user or governing workflow authorizes delegation. This skill does not require interviews for unrelated routine tasks.
