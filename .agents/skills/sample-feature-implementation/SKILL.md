# Educational feature sample

1. Read the requested feature, target APIs, existing sample conventions, and any supplied sample plan. Discover actual paths; no specific roadmap or sample directory is required.
2. Select one teaching objective and a compact representative scenario. Explain the problem, feature, value, correct use, and important limitations.
3. Use the consuming project's approved stack and real APIs. Keep fictional inputs visibly fictional and separate demonstration shortcuts from production requirements.
4. Include an incorrect example only when it teaches a concrete failure, with the expected diagnostic or behavior made clear.
5. Make the sample runnable or verifiable through the project's established commands. Verify the claimed behavior and report missing dependencies without inventing results.
6. Update relevant navigation and explain changed artifacts. A successful demonstration does not establish architecture acceptance or deployment authority.
